D37 — MCP-Graphiti Integration

#mcp #graphiti #integration #production

Contexto

El Orquestador necesita memoria persistente cross-session. Graphiti (Zep OSS) provee temporal knowledge graph con bi-temporal model. Se requiere integración vía MCP para exponer la memoria a otros agentes (Claude Desktop, Cursor) y al panel propio.

Decisión

Adoptar 3 transports MCP simultáneos:

  • stdio — para Claude Desktop (transporte nativo)
  • SSE — para Cursor IDE (Server-Sent Events)
  • HTTP — para nuestro panel Osquestador (con auth)

Implementación

# graphiti_mcp_server.py from fastapi import FastAPI from graphiti_mcp_server import mcp app = FastAPI(title="Graphiti Memory") @app.get("/health") async def health(): return {"status": "ok", "neo4j": "connected"} @app.post("/add_episode") async def add_episode(data: Episode): return await mcp.add_memory(data) @app.get("/search") async def search(q: str, group_id: str): return await mcp.search(q, group_id)

Consecuencias

Positivas:

  • Process isolation evita asyncio event loop conflicts
  • Independent scaling (CPU-bound agent vs I/O-bound graph)
  • Multiple agent instances contra single graph service
  • Technology-agnostic API boundary

Trade-offs:

  • Latency adicional por HTTP hop (~10-20ms)
  • Más complejidad operacional (2 containers)
  • Necesita health check + watchdog
